Package File

The following package file includes an NPM package file used by many FHIR tools. It contains the value sets, profiles, extensions, examples, page list, canonical URLs, CapabilityStatements, terminology resources, and other computable artefacts defined as part of this version of the Nigeria Core Implementation Guide.

This file SHOULD be the first choice whenever generating implementation artefacts, validating examples, configuring test servers, loading sandbox artefacts, or preparing conformance testing because it contains the computable rules about what makes the Nigeria Core profiles valid.

Implementers must still be familiar with the narrative specification content, conformance requirements, profile guidance, terminology rules, security expectations, and programme-specific guidance that apply to create a conformant implementation. See the [validating profiles and resources] documentation in FHIR for more information.

  • Package(compressed folder)

LLM-Ready View

This is an "LLM-ready" view of the Implementation Guide pages in Markdown format created from the static HTML pages. This format reduces the size of the IG and is designed to help an LLM, AI assistant, or documentation analysis tool handle the IG contents more easily.

  • llms.txt: An llms.txt manifest — a machine-readable index of the IG's Markdown files.
  • ai.zip: Markdown version of each HTML page bundled in a zip file.

Consolidated CSV and Excel File Representations of Profiles

All profile information for the Nigeria Core - FHIR Implementation Guide is available in single CSV and Excel file representations. These may be helpful to testers, analysts, programme teams, regulators, and implementers who need to review element properties, cardinalities, terminology bindings, Must Support flags, and constraints across profiles in a single table.

  • CSV(compressed folder)
  • Excel(compressed folder)

Additional summary spreadsheets may be provided where relevant to Nigeria Core implementation, programme alignment, or conformance testing. These may include summaries of Observation profiles, registry-related profiles, NG Patient Summary profiles, terminology mappings, or programme-specific profile comparisons.

  • NG Patient Summary Profiles Summary
  • Registry and Shared Services Profiles Summary

Terminology Artifacts

Terminology artefacts used in this guide are included in the package file and may also be available through generated terminology pages and downloadable resources.

Implementers SHOULD use the package file and terminology pages as the authoritative source for:

  • CodeSystems
  • ValueSets
  • ConceptMaps
  • NamingSystems
  • Identifier systems
  • Programme-specific terminology
  • Registry-related terminology
  • Local-to-international terminology mappings

Where terminology servers are used, these artefacts may be loaded into the Nigeria Core terminology service or sandbox terminology service for validation, expansion, and mapping.
