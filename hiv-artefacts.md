## HIV Programme Artefacts

This page provides a consolidated catalogue of the FHIR artefacts developed for the Nigeria HIV programme. It brings together foundational and clinical profiles, structured programme forms, completed form examples, programme registers and worksheets, aggregate reporting artefacts, terminology resources, mappings to established clinical terminologies, and exchange documents. Links are relative to the Implementation Guide and open the corresponding rendered FHIR artefact pages.

### Conformance Requirements

The keywords **SHALL**, **SHALL NOT**, **SHOULD**, **SHOULD NOT**, and **MAY** are normative and indicate the degree of conformance required by this guide already defined in [Conformace/General Requirements](general.md).

### Foundational Resources

These Nigeria Core profiles provide the patient, workforce, organisation, location, relationship, and encounter context required by HIV programme artefacts.

| | | |
| :--- | :--- | :--- |
| [NG Patient](StructureDefinition-ng-patient.md) | Represents the person receiving HIV prevention, testing, care, treatment, laboratory, pharmacy, transfer, or follow-up services. | Systems exchanging patient-level HIV data**SHALL**use this profile and populate all mandatory and Must Support elements relevant to the workflow. |
| [NG Practitioner](StructureDefinition-ng-practitioner.md) | Identifies clinicians, counsellors, pharmacists, laboratory personnel, and other health workers participating in HIV services. | Systems recording an individual health worker**SHALL**use this profile and preserve the practitioner's identifiers and professional details where available. |
| [NG PractitionerRole](StructureDefinition-ng-practitioner-role.md) | Represents the role, specialty, organisation, and service context in which a practitioner delivers HIV care. | Systems that exchange the practitioner's operational role**SHALL**use this profile and reference the associated Practitioner and Organization. |
| [NG RelatedPerson](StructureDefinition-ng-related-person.md) | Represents caregivers, treatment supporters, guardians, next of kin, and other persons related to an HIV client. | Systems exchanging related-person information**SHALL**use this profile and**SHALL**limit disclosure to the authorised care or programme purpose. |
| [NG Organization](StructureDefinition-ng-organization.md) | Identifies health facilities, laboratories, pharmacies, programme units, implementing partners, and other organisations involved in HIV services. | Systems**SHALL**use this profile for participating organisations and**SHALL**use nationally governed identifiers where available. |
| [NG Location](StructureDefinition-ng-location.md) | Represents the physical or service-delivery location where HIV services, specimen collection, dispensing, or follow-up occur. | Systems exchanging location information**SHALL**use this profile and reference the responsible Organization where applicable. |
| [NG Encounter](StructureDefinition-ng-encounter.md) | Provides the care-contact context for HIV assessment, counselling, treatment, laboratory, pharmacy, and follow-up activities. | Clinical HIV resources associated with a visit**SHOULD**reference a conformant encounter, and systems**SHALL**preserve encounter status, class, period, patient, and service location. |

### HIV Clinical Resources

These Nigeria Core clinical profiles support the extraction, persistence, exchange, and reuse of structured data collected through HIV programme forms and workflows.

| | | |
| :--- | :--- | :--- |
| [NG Condition](StructureDefinition-ng-condition.md) | Represents HIV diagnosis, opportunistic infections, tuberculosis, comorbidities, pregnancy-related conditions, and other clinically relevant problems. | Systems exchanging diagnoses or problem-list entries**SHALL**use this profile and apply the terminology binding defined for the coded condition. |
| [NG Observation](StructureDefinition-ng-observation.md) | Represents HIV test results, viral load, CD4, adherence findings, screening results, clinical measurements, and other observed data. | Systems exchanging observations**SHALL**use the applicable Nigeria Core Observation profile, preserve status and effective time, and use required codes and UCUM units where specified. |
| [NG ServiceRequest](StructureDefinition-ng-service-request.md) | Represents requests for laboratory tests, referrals, procedures, and other HIV-related services. | Systems creating or receiving HIV service orders**SHALL**use this profile and populate the patient, requester, requested service, status, intent, and supporting context. |
| [NG Specimen](StructureDefinition-ng-specimen.md) | Represents specimens collected for viral load, EID, CD4, drug-resistance, chemistry, haematology, and other HIV-related testing. | Laboratory workflows**SHALL**use this profile when specimen identity, type, collection, handling, or traceability is exchanged. |
| [NG DiagnosticReport](StructureDefinition-ng-diagnostic-report.md) | Groups and communicates authorised HIV laboratory or diagnostic results and their interpretations. | Systems issuing diagnostic reports**SHALL**use this profile, reference the relevant ServiceRequest, Specimen, and Observation resources where available, and preserve report status. |
| [NG MedicationRequest](StructureDefinition-ng-medication-request.md) | Represents prescribed ART, PrEP, PEP, TB preventive therapy, opportunistic-infection medicines, and related treatments. | Prescribing systems**SHALL**use this profile, identify the patient and prescriber, and use the applicable medication terminology and dosage instructions. |
| [NG MedicationStatement](StructureDefinition-ng-medication-statement.md) | Represents medicines reported as currently or previously taken by the client, including prior ART and transferred-in regimens. | Systems exchanging medication history**SHALL**use this profile and distinguish reported use from an active prescription or dispensing event. |
| [NG AllergyIntolerance](StructureDefinition-ng-allergy-intolerance.md) | Represents allergies, intolerances, and clinically relevant adverse reactions affecting HIV treatment choices. | Systems exchanging allergy information**SHALL**use this profile and preserve verification status, clinical status, substance, and reaction details where known. |
| [NG Procedure](StructureDefinition-ng-procedure.md) | Represents completed HIV-related procedures and interventions that are not adequately represented as observations or medication events. | Systems claiming Procedure support**SHALL**use this profile and record patient, status, performed time, performer, and coded procedure where applicable. |
| [NG Flag](StructureDefinition-ng-flag.md) | Represents actionable HIV care alerts, cautions, follow-up warnings, or programme attention markers. | Systems using flags**SHALL**state the flag status, category, code, subject, and applicable period, and**SHALL**protect sensitive flag content from unauthorised disclosure. |
| [NG Task](StructureDefinition-ng-task.md) | Coordinates HIV referrals, specimen movement, follow-up, treatment actions, pharmacy fulfilment, and other workflow assignments. | Workflow systems**SHALL**use this profile when exchanging actionable work and**SHALL**preserve task status, intent, owner, focus, and business identifiers. |

### Implementation Guidance

Implementers should use the Questionnaire artefacts to create interoperable electronic HIV forms and corresponding QuestionnaireResponse resources to represent completed submissions. Where structured clinical reuse is required, QuestionnaireResponse content should be extracted or mapped to the applicable foundational and clinical profiles.

Logical models provide programme-oriented definitions for registers and worksheets and should be mapped to appropriate clinical, administrative, medication, laboratory, workflow, and reporting FHIR resources. Measure artefacts define computable indicator logic, while MeasureReport resources carry the aggregate results for a defined reporting period.

CodeSystems define authoritative programme codes. ValueSets identify the codes permitted for specific data elements and reporting disaggregations. ConceptMaps support translation between Nigeria HIV local concepts, LOINC, and SNOMED CT; mappings should be validated through programme and terminology governance before use in clinical decision-making.

Implementations **SHALL** preserve published canonical URLs, identifiers, terminology system URIs, code-system versions where supplied, references, cardinalities, invariants, and required bindings. HIV data and documents **SHALL** be exchanged only for authorised purposes and protected in accordance with applicable privacy, security, consent, audit, and data-minimisation requirements.
