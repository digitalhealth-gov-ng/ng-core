ActorDefinition: NG Requestor

Official URL: https://fhir-ig.digitalhealth.gov.ng/ActorDefinition/NgCoreRequestor Version: 0.0.0
Draft as of 2026-08-17 Computable Name: NgCoreRequestor
Other Identifiers: OID:2.16.840.1.113884.3.9944.1.12.3

A client application or service that initiates FHIR requests or exchanges using the Nigeria Core specifications.

Defines the system role responsible for initiating interoperable exchanges with Nigeria Core conformant services. A deployed system may act as a Requestor, Responder, or both, depending on the workflow.

Actor: NgCoreRequestor Nigeria Core RequestorType: system

Role

The Nigeria Core Requestor is an authorised application or service that initiates interactions with a FHIR-enabled service.

Examples include EMR/EHR systems, facility applications, mobile and community health applications, laboratory, pharmacy and imaging systems, program systems, HIEs, registries, middleware, and reporting applications.

Responsibilities

A Requestor may:

  • retrieve information using supported read, search, and other interactions;
  • create, update, submit, or exchange FHIR resources and Bundles;
  • invoke supported FHIR operations;
  • query registry and terminology services;
  • submit resources for validation or conformance testing; and
  • process successful responses and OperationOutcome results.

Conformance expectations

A Requestor SHALL:

  • construct requests conforming to applicable Nigeria Core profiles;
  • provide mandatory and applicable Must Support elements;
  • use governed identifiers and terminology where required;
  • preserve required references and relationships;
  • use only interactions and operations supported by the receiving service; and
  • appropriately process FHIR responses and errors.

The Requestor SHOULD inspect the receiving service's CapabilityStatement before relying on optional capabilities and SHALL NOT assume that every Responder supports every Nigeria Core resource, operation, search parameter, or program profile.

Applicable national authentication, authorisation, privacy, consent, audit, and secure-exchange requirements SHALL be followed.

Relationships

The Requestor commonly interacts with the Nigeria Core Responder, Registry Service, Terminology Service, and Conformance and Sandbox Service.

A single implementation may perform multiple actor roles.
